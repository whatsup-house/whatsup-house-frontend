인자로 받은 내용을 바탕으로 Jira 일감 등록 계획을 수립하고, 사용자 승인 후 KAN 프로젝트에 이슈를 생성한다.

인자가 없으면 "등록할 일감 내용을 인자로 전달하세요. 예: /create-jira 로그인 페이지 유효성 검사 추가"를 출력하고 종료한다.

## 1단계: 이슈 유형 판단

인자($ARGUMENTS)와 대화 맥락을 바탕으로 아래 유형 중 하나를 결정한다.

| 유형 | issueTypeName | 판단 기준 |
|------|--------------|-----------|
| Feature | `Feature` | 신규 기능, 페이지, API 구현 |
| Bug | `Bug` | 오류, 에러, 깨진 동작, 수정 |
| Task | `Task` | 리팩터링, 설정, 문서, 환경 구성 |

우선순위도 판단한다: `Highest` / `High` / `Medium` / `Low`
- 결제·인증·데이터 손실 관련 → High 이상
- 일반 기능 → Medium
- 개선·리팩터링 → Low

### FE/BE 분리 원칙 (필수)

하나의 요청에 프론트엔드와 백엔드 작업이 함께 필요하면 **반드시 `[FE]`와 `[BE]` 두 개의 이슈로 나눠서 작성한다.** `[FE/BE]` 하나로 묶지 않는다.

- 분리 기준
  - `[FE]`: 화면/컴포넌트, 클라이언트 상태, API 호출(요청·응답 처리), 폼/유효성 등
  - `[BE]`: API 엔드포인트, 비즈니스 로직, DB 스키마/마이그레이션, enum·매핑 리소스 등
- 각 이슈는 상대 이슈에 의존하는 부분을 `[연관 일감]` 항목에 명시한다.
- 작업이 한쪽(FE만 또는 BE만)으로 끝나면 분리하지 않고 한 개로 작성한다.
- 여러 개선사항이 한 번에 들어오면 사안별로 위 규칙을 각각 적용한다. (사안 N개 × FE/BE = 총 이슈 수)

## 2단계: KAN-1 템플릿 기반 이슈 초안 작성

이슈 유형에 따라 아래 템플릿을 채운다.
현재 프로젝트 컨텍스트(프론트엔드 여부, 관련 도메인 등)를 최대한 반영한다.

### Feature / Task 템플릿

```
[설명]
* (한 문장으로 기능/작업 설명)

[요구사항]
* (구현해야 할 사항을 bullet로)
* (제약 조건)
* (인증 필요 여부)

[API]
* (Method) (URL) — 없으면 "해당 없음"

[Request]
* (요청 필드 및 타입) — 없으면 "해당 없음"

[Response]
* (응답 필드 및 상태값) — 없으면 "해당 없음"

[DB]
* (관련 테이블 및 연관 관계) — 프론트 전용이면 "해당 없음"

[예외]
* (예외 케이스 → HTTP 상태코드)
```

### Bug 템플릿

```
[설명]
* (버그 한 문장 설명)

[재현 조건]
* (어떤 상황에서 발생하는지)
* (재현 순서)

[현재 동작]
* (잘못된 동작)

[기대 동작]
* (올바른 동작)

[원인 분석]
* (파악된 원인 — 모르면 "미파악")

[수정 범위]
* (수정이 필요한 파일/함수/로직)

[예외]
* (관련 에러 코드나 엣지 케이스)
```

## 3단계: 초안 출력 및 사용자 확인

### 제목 형식 규칙

제목은 반드시 아래 형식을 따른다.

```
[FE] 한국어 제목    ← 프론트엔드 작업
[BE] 한국어 제목    ← 백엔드 작업
```

`[FE/BE]` 접두사는 사용하지 않는다. 풀스택 작업은 1단계 'FE/BE 분리 원칙'에 따라 `[FE]`·`[BE]` 두 이슈로 나눠 각각의 제목을 단다.

예시:
- `[FE] 이미지 업로드 시 비율별 크롭 에디터 UI 구현`
- `[BE] 리뷰 작성 시 마일리지 적립 정책 보완`
- `[FE] BottomNav 소셜 탭 비활성화 및 3탭 균등 재배치`

인자나 대화 맥락에서 프론트/백엔드 여부를 파악한다. 명확하지 않으면 `[FE]`를 기본으로 사용한다.

---

아래 형식으로 출력한 뒤 **반드시 사용자에게 확인을 받는다.**

```
📋 Jira 등록 계획

제목: (작성한 summary)
유형: (Feature / Bug / Task)
우선순위: (Highest / High / Medium / Low)

설명:
(작성한 description 전문)

---
Jira에 등록할까요?
```

사용자가 수정을 요청하면 해당 내용을 반영해 초안을 다시 출력하고 다시 확인을 받는다.
사용자가 "응", "ㅇㅇ", "등록", "yes", "y" 등 긍정 응답을 하면 4단계로 진행한다.

## 4단계: Jira 이슈 생성

3단계에서 확정한 이슈를 **각각** `mcp__claude_ai_Atlassian_Rovo__createJiraIssue`로 생성한다. (FE/BE로 나뉘었거나 여러 사안이면 이슈 개수만큼 반복 생성한다.)

- cloudId: `d4081ac1-010a-45f5-8241-d9d67209e21b`
- projectKey: `KAN`
- issueTypeName: (3단계에서 결정한 유형)
- summary: (3단계에서 작성한 제목)
- description: (3단계에서 작성한 설명 전문)
- contentFormat: `markdown`
- additional_fields:
  - priority: `{ "name": "(결정한 우선순위)" }`
  - assignee_account_id: `712020:5c7166ce-43b2-42c3-9acf-8c0a495dbaf4`

생성 완료 후 만들어진 이슈를 모두 출력한다.

```
✅ Jira 이슈가 등록됐습니다.
KAN-XXX: (summary)
https://whatsuphouse.atlassian.net/browse/KAN-XXX
```

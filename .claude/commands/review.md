현재 브랜치에서 변경된 파일을 `frontend-reviewer` 에이전트에 위임해 프로젝트 규칙 준수를 검토한다.

> 역할 구분: 이 명령어는 **프로젝트 규칙 위반**(구조/타입/상태관리/스타일)을 검사한다.
> 버그·정합성 리뷰는 내장 `/code-review`를 사용한다. 둘은 상호 보완이다.

다음 순서로 진행한다:

1. `git diff develop --name-only`로 변경된 파일 목록을 확인한다.
   목록이 비어있으면 "변경된 파일이 없습니다"를 출력하고 종료한다.

2. `Agent` 도구로 `frontend-reviewer` 서브에이전트를 호출한다.
   프롬프트에는 **변경 파일의 경로 목록만** 포함한다 — 파일 내용을 복붙하지 않는다.
   에이전트가 직접 파일과 `.claude/rules/frontend/` 규칙을 읽고 검토한다.

3. 에이전트의 검토 결과를 그대로 출력한다.
   "문서-코드 불일치 의심" 항목이 있으면 규칙 문서 갱신 필요 여부를 사용자에게 알린다.

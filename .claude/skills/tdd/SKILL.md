# 테스트 작성 규칙 (TDD & 테스트 품질)

이 스킬의 목적은 **테스트 개수나 커버리지 숫자가 아니라, 회귀를 실제로 잡는 테스트**를 만드는 것이다.
커버리지를 올리는 작업(소나큐브 품질 게이트 대응 등)에서 특히 이 문서를 지켜라 — 숫자만 채우는 테스트는 유지보수 부채다.

---

## 시작 전 합의 (필수)

테스트를 쓰기 전에 **무엇을 검증할지**를 먼저 선언하고 사용자 승인을 받는다:

```
검증 대상: {클래스/모듈}의 공개 인터페이스 {메서드/함수 목록}
검증 경계(seam): {예: Service 단위 — Repository는 mock / Repository 슬라이스 — 실제 쿼리 검증}
제외: {검증하지 않을 것과 이유}
```

경계를 합의하지 않으면 "무엇이든 mock하는 테스트"가 되고, 그런 테스트는 리팩토링 때 전부 깨진다.

---

## 레드-그린 루프 (테스트 먼저 요청 시)

1. **레드**: 실패하는 테스트를 하나 쓴다. 실행해서 **실패를 눈으로 확인**한다. 실패 메시지가 의도(기대 동작)를 설명하는지 본다.
2. **그린**: 그 테스트를 통과시키는 최소한의 구현을 쓴다. 실행해서 통과를 확인한다.
3. **리팩토링**: 테스트를 초록으로 유지한 채 코드를 정리한다.
4. 반복. **한 루프에 테스트 하나.** 테스트 10개를 먼저 다 쓰고 구현하는 것은 TDD가 아니다.

레드 단계를 건너뛰지 마라 — 실패를 본 적 없는 테스트는 "항상 통과하는 테스트"일 수 있다.

---

## 좋은 테스트의 조건

- **공개 인터페이스만 검증한다.** private 메서드, 내부 상태, 호출 순서가 아니라 입력→출력/부수효과를 검증한다.
- **리팩토링 내구성**: 동작이 같은데 구현을 바꿨을 때 깨지면 나쁜 테스트다.
- **테스트명이 명세다**: `취소된_신청은_이용권을_환불한다` (O) / `testCancel2` (X)
- **하나의 테스트는 하나의 규칙**을 검증한다. assert 20개짜리 테스트는 쪼갠다.

## 안티패턴 (발견 시 작성 금지 / 리뷰 시 지적)

| 안티패턴 | 증상 | 왜 나쁜가 |
|---|---|---|
| **동어반복** | mock이 반환하게 시킨 값을 그대로 assert | 구현이 아니라 mock 설정을 검증. 버그를 못 잡음 |
| **구현 결합** | `verify(repo, times(3))` 같은 내부 호출 횟수 검증 남발 | 리팩토링마다 깨짐. 동작은 안 지켜줌 |
| **커버리지 채우기** | getter/builder/DTO만 도는 테스트 | 숫자는 오르는데 회귀 방어력 0 |
| **수평 분할** | 해피패스만 10개 변형 | 경계값·예외 경로가 진짜 버그 서식지 |
| **거대 셋업** | 테스트마다 50줄 fixture 복붙 | 의도가 묻힘. 팩토리/빌더로 추출 |

## 무엇부터 테스트할까 (우선순위)

1. **돈·자격이 걸린 로직**: 이용권 차감/환불, 마일리지, 결제 상태 전이
2. **상태 머신**: Application/Gathering 상태 전이 (허용되지 않는 전이가 막히는지)
3. **동시성 가드**: 정원 락, 중복 신청 방지 — 실패 시나리오 포함
4. **경계값과 예외 경로**: 정원 == max, 만료 직전 토큰, 삭제된 엔티티 참조
5. 마지막이 해피패스다. 해피패스는 대부분 e2e/실행 검증이 이미 커버한다.

## 스택별 도구

### BE (Spring Boot) — 백엔드 레포 `.claude/skills/testing` 스킬과 함께 사용
- Service 단위 테스트: Mockito로 Repository만 mock. 다른 Service를 mock하기 시작하면 경계 재합의.
- Repository 슬라이스: `@DataJpaTest` — soft delete 필터(`DeletedAtIsNull`)가 실제로 먹는지 이 레벨에서 검증.
- 실행: `./gradlew test --tests "..."` 로 해당 테스트만 빠르게 반복.

### FE (Next.js)
- 유틸/훅 로직 위주로만 단위 테스트 (프로젝트 정책: 테스트 최소주의).
- 화면 동작은 Playwright e2e 또는 `.claude/skills/webapp-testing/` 스킬로 실행 검증.
